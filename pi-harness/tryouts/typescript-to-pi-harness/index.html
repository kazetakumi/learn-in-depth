TypeScript, all the way down to a working agent harness

Eight rungs. Each one's payoff is the next one's floor.

You asked to learn TypeScript from scratch and end up building something like pi. So I built this backward from the ending, not forward from a syllabus. Every rung below is here because the harness cannot be written without it. Nothing is here because a course happened to cover it.

You think in Python. I'm going to use that relentlessly — duck typing, TypeVar, Pydantic, async for. You own more of this than you think. What you don't own is JavaScript's runtime, so that's rung 0.

A warning I'd rather give now than at rung 6. I searched all four of your transcripts for await, yield, generator, and iterator. Zero hits. Not one, across 187,000 words.

Those courses teach TypeScript's type system and assume you already own JavaScript's runtime. But pi's agent loop is for await (const event of response) — an async iterator. So rungs 0 and 5 come from primary sources and pi's own code instead. The transcripts carry rungs 1 through 4, which is exactly what they're good at.

The ladder

  1. The machine underneath

    JavaScript has one thread and it must never stop. So “not yet” has to become a value you can hold in your hand.

    Payoff: the Promise, derived rather than defined — and the seed of the whole harness, because an LLM response is the ultimate not-yet.

  2. A type is a set of values

    Everything TypeScript does is set membership. extends means ⊆. Read it that way once and nothing in the language is magic again.

    Payoff: structural typing, never as ∅, unknown as 𝕌, and erasure — why TS types can’t be inspected at runtime the way yours can.

  3. Narrowing is set arithmetic

    A union is a set union. Narrowing shrinks it. Exhaustiveness checking works because what’s left over at the end is the empty set.

    Payoff: discriminated unions — how every message and every stream event in pi is modelled. AssistantMessageEvent has twelve members.

  4. Generics: functions from types to types

    You already write functions over values. These are functions over sets — and their constraints are just ⊆ again, which you’ll already own.

    Payoff: Tool<TSchema> — a tool whose argument type is a parameter.

  5. Types that compute

    Conditional types are pattern matching on sets. infer is destructuring. The type system is a language and you can run programs in it.

    Payoff: Static<T> — deriving a tool’s argument type from its JSON schema. Your Pydantic moment, except it costs nothing at runtime.

  6. Async as a stream

    A Promise is one not-yet. An async generator is a whole sequence of them. An LLM response is exactly that, arriving token by token.

    Payoff: for await (const event of response) — the single line the entire harness is built around.

  7. Build: the harness spine

    Every rung so far was load-bearing for one while-loop. Now you write it.

    Payoff: typed tool registry, streaming provider call, the agent loop, tool execution. Around 300 lines you can defend line by line.

  8. Build: the CLI agent

    Make it a thing you actually use, not a thing you finished.

    Payoff: stdin/stdout, streaming render, read/write/bash tools. A working coding agent with your name on it.

What I cut, and why

You chose depth over coverage, so the following came out of the transcripts and did not make the ladder:

  • enum — pi’s own AGENTS.md forbids it outright, along with namespace, under its erasable-syntax-only rule.
  • Decorators — pi uses none.
  • Deep class and OOP material — two transcripts spend hours here; the harness needs almost none of it.
  • The React sections — different problem entirely.
  • The utility-type catalogue (Pick, Omit, Partial…) — these are downstream of rung 4. Once you can write Extract yourself they take five minutes, and a lecture on them before rung 4 would be memorisation.

If any of that turns out to be load-bearing later, we add a rung. The ladder is allowed to change; it just isn’t allowed to grow for the sake of completeness.
